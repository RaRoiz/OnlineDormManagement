# Online Dorm Management — ระบบจัดการหอพักออนไลน์

เว็บแอปพลิเคชันสำหรับบริหารจัดการ **หอพักเดียว** ครอบคลุมข้อมูลห้องพัก ผู้เช่า มิเตอร์น้ำและไฟฟ้า ใบแจ้งหนี้ หลักฐานการชำระเงิน และรายงาน โดยใช้ Google Apps Script เป็น Backend, Google Sheets จัดเก็บข้อมูล และ Google Drive จัดเก็บรูปภาพ

ผู้ดูแลระบบ เจ้าของหอพัก และพนักงานใช้งานผ่านหน้าเว็บ ส่วนผู้เช่ารับใบแจ้งหนี้และส่งสลิปผ่าน LINE ไม่ต้องสมัครบัญชีพนักงาน

เอกสารนี้อ้างอิงโค้ดในโปรเจ็กต์ ไม่ใช่การยืนยันว่าเว็บไซต์และ Apps Script ที่เผยแพร่กำลังใช้เวอร์ชันเดียวกัน

## ฟังก์ชันหลัก

| ส่วนงาน | ความสามารถ |
|---|---|
| บัญชีผู้ใช้ | เข้าสู่ระบบ สมัครพนักงานด้วยรหัสเชิญ กำหนดสิทธิ์ตามบทบาท เปิด–ปิดบัญชี และรีเซ็ตรหัสผ่านโดย ADMIN |
| โปรไฟล์ | แก้ไขข้อมูลติดต่อ เปลี่ยนรหัสผ่าน อัปโหลดรูปพร้อมซูมและปรับตำแหน่งก่อนครอปเป็น 512×512 พิกเซล |
| ห้องพัก | ดู ค้นหา เพิ่ม แก้ไข และลบตามสิทธิ์ |
| ผู้เช่า | เพิ่มและแก้ไขข้อมูล เชื่อมโยงกับห้องพัก และบันทึกการย้ายออก |
| มิเตอร์ | บันทึกและแก้ไขมิเตอร์น้ำ–ไฟ คำนวณค่าใช้จ่ายตามข้อมูลที่กำหนด |
| ใบแจ้งหนี้ | สร้างจากรายการมิเตอร์ รวมค่าเช่าและค่าใช้จ่ายเพิ่มเติม พิมพ์บิล แสดง QR พร้อมเพย์ และส่ง LINE |
| การชำระเงิน | บันทึกชำระเงิน ดูสลิป ยืนยันหรือปฏิเสธพร้อมเหตุผล และเก็บประวัติการตรวจ |
| LINE | ลงทะเบียนผูกห้อง รับใบแจ้งหนี้ ส่งสลิป และรับผลการตรวจสอบ |
| รายงาน | Dashboard และรายงานห้องพัก ผู้เช่า ค่าสาธารณูปโภค และใบแจ้งหนี้ สำหรับ OWNER/ADMIN |
| หน้าจอ | รองรับธีมสว่าง/มืดและการจัดวางสำหรับหน้าจอขนาดต่าง ๆ |

**ระบบไม่ได้ตรวจธุรกรรมกับธนาคารอัตโนมัติ** การรับรูปสลิปไม่เท่ากับการยืนยันว่าชำระเงินสำเร็จ ผู้มีสิทธิ์ต้องตรวจสอบหลักฐานก่อนยืนยัน

## บทบาทและสิทธิ์

| การใช้งาน | ADMIN | OWNER | USER (พนักงาน) |
|---|:---:|:---:|:---:|
| จัดการโปรไฟล์ของตนเอง | ✓ | ✓ | ✓ |
| ดูข้อมูลห้องพัก | ✓ | ✓ | ✓ |
| เพิ่ม/แก้ไข/ลบห้องพัก | ✓ | ✓ | — |
| เพิ่ม/แก้ไขผู้เช่าและบันทึกย้ายออก | ✓ | ✓ | ✓ |
| เพิ่ม/แก้ไขมิเตอร์ | ✓ | ✓ | ✓ |
| ลบผู้เช่าหรือมิเตอร์ | ✓ | ✓ | — |
| สร้าง/แก้ไข/ลบบิล พิมพ์ ส่ง LINE และบันทึกชำระเงิน | ✓ | ✓ | ✓ |
| ดูและตรวจสอบสลิป | ✓ | ✓ | ✓ |
| ตั้งค่าพร้อมเพย์/LINE ดูพนักงานและลิงก์เชิญ | ✓ | ✓ | — |
| Dashboard และรายงาน | ✓ | ✓ | — |
| จัดการบัญชีผู้ใช้ | ✓ | — | — |

สิทธิ์ข้างต้นยังอยู่ภายใต้เงื่อนไขข้อมูล เช่น บิลที่ชำระแล้วแก้ไขหรือลบไม่ได้ และบิลรอตรวจสอบต้องยืนยันผ่านขั้นตอนตรวจสลิป โค้ด Backend ใช้ `ownerOnly_`, `adminOnly_` และการตรวจในแต่ละ handler ไม่ได้อาศัยการซ่อนปุ่มเพียงอย่างเดียว

- `USER` อาจแสดงบนหน้าจอเป็น `STAFF`
- บทบาทหลักของผู้ดูแลระบบคือ `ADMIN` และรองรับค่าเก่า `SUPER_ADMIN` ระหว่างเปลี่ยนผ่าน
- `migrateSuperAdminRoleToAdmin()` ใช้เปลี่ยนค่าบทบาทเก่าในชีต โดยไม่เปลี่ยนชื่อบัญชีหรือรหัสผ่าน
- ผู้เช่าผ่าน LINE ไม่ใช่บทบาท `USER` ของเว็บ

## โครงสร้างและเทคโนโลยี

```text
Frontend (Vite + TypeScript) ── JSON API ── Google Apps Script
                                                ├── Google Sheets: ข้อมูลระบบ
                                                ├── Google Drive: รูปโปรไฟล์/สลิป
ผู้เช่า ── LINE OA ── Webhook / Messaging API ────┘
```

Frontend เป็นแอปหลายหน้า ไม่ใช้ UI framework หลัก มี CSS กลางและไลบรารี `qrcode` ส่วน Backend รับคำขอผ่าน `doPost` และใช้ CacheService สำหรับเซสชันและข้อมูลบางรายการ

```text
OnlineDormManagement/
├── frontend/
│   ├── index.html / login.html
│   ├── package.json
│   └── src/
│       ├── pages/         # room, tenant, meter, bill, report, profile, staff, admin, register
│       ├── services/      # เรียก API
│       ├── types/         # ชนิดข้อมูลและ API_URL
│       ├── styles/        # ธีมและรูปแบบร่วม
│       └── utils/         # สิทธิ์ หน้าต่าง รูปโปรไฟล์ และการครอป
├── backend/
│   ├── Code.js            # Router
│   ├── Auth.js / Admin.js / Settings.js
│   ├── Room.js / Tenant.js / Meter.js / Bill.js / Report.js
│   ├── Arrears.js / Performance.js
│   ├── Line.js            # ไฟล์ local ที่ถูก Git ignore
│   ├── LineBinding.js     # ตรวจความสัมพันธ์ LINE–ผู้เช่า–ห้อง
│   ├── Slips.js / SlipReview.js / Avatars.js
│   ├── Setup.js / Migration.js / RoleMigration.js
```

ชีตหลัก ได้แก่ `Users`, `Rooms`, `Tenants`, `Meters`, `Bills`, `LineLinks`, `PaymentSlips` และ `SlipReviews` โดยฟังก์ชันของแต่ละโมดูลสร้างหรือเตรียมชีตเมื่อเรียกใช้งาน ควรใช้ชื่อหัวคอลัมน์ตามโค้ด ไม่เปลี่ยนชื่อเองโดยไม่ตรวจผลกระทบ

## ติดตั้งและรัน Frontend

ใช้ Node.js ที่ตรงกับข้อกำหนดของ Vite ในโปรเจ็กต์: `20.19+` ในสาย 20 หรือ `22.12+` ขึ้นไป และมี npm

```bash
cd frontend
npm ci
npm run dev
```

เปิด URL ที่ Vite แสดงใน terminal จากนั้นตั้ง `API_URL` ใน [frontend/src/types/api.ts](frontend/src/types/api.ts) ให้เป็น URL Apps Script Web App ที่ลงท้าย `/exec`

```bash
npm run build
npm run preview
```

`build` ตรวจ TypeScript และสร้างไฟล์ใน `frontend/dist/` ส่วน `preview` ใช้เปิดผล build ในเครื่อง

## เตรียม Backend

### 1. เตรียมไฟล์และโปรเจ็กต์ Apps Script

สร้าง Google Spreadsheet และโปรเจ็กต์ Apps Script ของระบบ จากนั้นใช้ clasp หรือ Apps Script editor เพื่อนำไฟล์ใน `backend/` ขึ้นโปรเจ็กต์

**ข้อจำกัดของการ clone:** `.gitignore` ไม่ติดตาม `backend/Line.js` และไฟล์เชื่อมโยง clasp บางตำแหน่ง ผู้ติดตั้งต้องขอ `Line.js` จากผู้ดูแลผ่านช่องทางที่เหมาะสม และเชื่อม clasp กับโปรเจ็กต์ของตนเองก่อน ระบบ LINE และชุดทดสอบบางส่วนจะไม่ครบหากไม่มีไฟล์นี้ ไม่ควรนำค่าลับหรือไฟล์ที่มี token ขึ้น GitHub

เมื่อติดตั้ง clasp และตั้งค่าการเชื่อมโยงแล้ว:

```bash
clasp login
cd backend
clasp status
clasp push
```

ตรวจว่า clasp ชี้ไปยังโปรเจ็กต์และรายการไฟล์ที่ต้องการก่อน push บน Windows PowerShell สามารถใช้ `clasp.cmd` และ `npm.cmd` หากคำสั่ง `.ps1` ถูก Execution Policy บล็อก

### 2. ตั้ง Script Properties

กำหนดค่าที่ Apps Script → Project Settings → Script Properties ไม่ใช้ URL ของ Vercel แทน Spreadsheet ID หรือ Apps Script ID

| Property | วัตถุประสงค์ |
|---|---|
| `SPREADSHEET_ID` | ID ของ Spreadsheet ที่จัดเก็บข้อมูลระบบ จำเป็นต่อการใช้งาน |
| `INITIAL_SUPERADMIN_PASSWORD` | รหัสผ่านสำหรับสร้างหรือกู้บัญชีผู้ดูแลระบบผ่าน `createInitialSuperAdmin()` |
| `INITIAL_ADMIN_PASSWORD` | ใช้เฉพาะเมื่อสร้างบัญชี OWNER ผ่าน `createInitialAdmin()` |
| `STAFF_SIGNUP_CODE` | รหัสเชิญสมัครพนักงาน ควรเป็นค่าที่คาดเดายากและส่งให้ผู้ได้รับเชิญเท่านั้น |
| `FRONTEND_URL` | URL เว็บที่พนักงานเปิดได้จริง ใช้สร้างลิงก์เชิญ หากไม่ตั้งจะใช้ค่าเดิมใน `invite-link.ts` |
| `PROMPTPAY_ID` | หมายเลขพร้อมเพย์สำหรับสร้าง QR |
| `LINE_CHANNEL_ACCESS_TOKEN` | Token สำหรับส่งข้อความผ่าน LINE Messaging API |
| `LINE_BOT_USER_ID` | ข้อมูลบัญชีบอต LINE ที่ระบบรองรับ |
| `SLIP_FOLDER_ID` | ID โฟลเดอร์สลิป ใส่เฉพาะ ID ไม่ใส่ URL หรือ `/folders/` |
| `PRIVATE_SLIP_FOLDER_ID` | ระบบบันทึกเมื่อสร้างโฟลเดอร์สำรองส่วนตัว ไม่จำเป็นต้องตั้งเองตามปกติ |
| `DORM_NAME` | ค่าเสริมที่ยังรองรับใน Backend ไม่ใช่เงื่อนไขบังคับของหน้าสมัครพนักงาน |

URL ของ Frontend และ Apps Script ทำหน้าที่ต่างกัน: `FRONTEND_URL` ใช้เปิดหน้าเว็บ ส่วน `API_URL` ใช้เรียก Backend และ URL `/exec` ใช้เป็น Webhook ของ LINE ด้วย

### 3. สร้างบัญชีเริ่มต้นและอนุญาตสิทธิ์

| ฟังก์ชันที่รันใน Apps Script editor | ชื่อบัญชี | บทบาทจริง |
|---|---|---|
| `createInitialSuperAdmin()` | `superadmin` | `ADMIN` |
| `createInitialAdmin()` | `admin` | `OWNER` |

ชื่อฟังก์ชันและชื่อบัญชีเดิมยังคงอยู่ แม้เปลี่ยนชื่อบทบาทเป็น `ADMIN` แล้ว หากรัน `createInitialSuperAdmin()` ซ้ำ ระบบจะตั้งรหัสผ่านใหม่ตาม Script Property และเปิดใช้งานบัญชีนั้นอีกครั้ง จึงไม่ใช่ฟังก์ชันสำหรับรันทุกครั้งที่ deploy

อนุญาตสิทธิ์ตาม `appsscript.json` สำหรับ Sheets, Drive และการเรียกบริการภายนอก ใช้ `authorizeDriveAccess()` เพื่อเริ่มขั้นตอนอนุญาต Drive และ `checkSlipFolder()` เพื่อตรวจโฟลเดอร์สลิป

### 4. เผยแพร่ Web App

เผยแพร่เป็น Web App โดยให้ทำงานด้วยบัญชีผู้เผยแพร่ และเปิดการเข้าถึงให้ LINE Webhook/Frontend เรียกได้ตามรูปแบบใน manifest จากนั้นนำ URL `/exec` ไปตั้งใน Frontend

**`clasp push` อัปเดตไฟล์ แต่ไม่ได้ทำให้ deployment เดิมใช้โค้ดใหม่ทันที** หลังเปลี่ยน Backend ให้แก้ deployment เดิม เลือกเวอร์ชันใหม่ และ deploy อีกครั้ง หากสร้าง deployment ใหม่จน URL เปลี่ยน ต้องแก้ทั้ง `API_URL` และ LINE Webhook ให้ตรงกัน

## ตั้งค่า LINE และกระบวนการรับสลิป

1. เตรียม LINE Official Account ที่เปิดใช้ Messaging API และตั้ง Access Token ใน Script Properties
2. ตั้ง Webhook URL เป็น Apps Script `/exec` และเปิดรับ webhook
3. ทดสอบส่งข้อความจริง พร้อมตรวจ Apps Script Executions หากไม่ได้รับการตอบกลับ ไม่ถือว่า HTTP 302 หรือการ Verify ล้มเหลวเป็นหลักฐานว่าใช้งานได้ตามปกติ
4. ผู้เช่าส่งเลขห้องเพื่อผูกบัญชี LINE กับผู้เช่าที่มีสถานะ ACTIVE
5. เจ้าหน้าที่ส่งใบแจ้งหนี้จากหน้าเว็บ ผู้เช่าส่งภาพสลิปกลับผ่าน LINE
6. ระบบตรวจความสัมพันธ์ของผู้ส่ง ผู้เช่า ห้อง และบิล ก่อนจัดเก็บและเปลี่ยนสถานะเป็นรอตรวจสอบ

การผูก LINE ที่ซ้ำ การพยายามเปลี่ยนผู้เช่าที่ผูกไว้ หรือข้อมูลห้องไม่ตรงกันจะถูกปฏิเสธ ให้ผู้ดูแลตรวจข้อมูลก่อนเปลี่ยนการผูก ไม่ควรลบหรือย้ายหลักฐานการชำระเงินโดยคาดเดาจากเลขห้องเพียงอย่างเดียว

### สถานะใบแจ้งหนี้

| สถานะ | ความหมาย |
|---|---|
| `UNPAID` | ยังไม่ยืนยันการชำระเงิน |
| `PENDING` | ได้รับสลิปและรอตรวจสอบ |
| `PAID` | ผู้มีสิทธิ์ยืนยันว่าชำระแล้ว |
| `OVERDUE` | สถานะที่หน้าเว็บใช้แสดงเมื่อยังไม่ชำระและพ้นกำหนด ไม่ใช่ผลยืนยันจากธนาคาร |

- ยืนยันสลิป: เปลี่ยนเป็น `PAID` และบันทึกผู้ตรวจ/เวลา/หลักฐาน
- ปฏิเสธสลิป: ต้องระบุเหตุผล บิลกลับเป็น `UNPAID` และแจ้งให้ผู้เช่าส่งใหม่
- เมื่อมีสลิปรอตรวจสอบ ระบบไม่โยนภาพถัดไปเข้าบิลค้างอีกใบโดยอัตโนมัติ
- สลิปใหม่หลังถูกปฏิเสธจะเลือกบิลเดิมก่อน หากกำกวมหรือพบบิลซ้ำ ระบบขอให้ติดต่อผู้ดูแล
- หากข้อมูลบิลหรือสลิปเปลี่ยนหลังเปิดหน้าตรวจ ต้องเปิดตรวจใหม่ก่อนยืนยัน
- การแจ้ง LINE ล้มเหลวหลังบันทึกผลตรวจไม่ย้อนผลการตรวจที่บันทึกแล้ว หน้าเว็บจะแจ้งให้ติดต่อผู้เช่าโดยตรง

## รูปภาพและสิทธิ์ Google Drive

**สลิป:** ใช้ `SLIP_FOLDER_ID` หรือโฟลเดอร์ `DormManagement Slips` ตามการตั้งค่า หากพบโฟลเดอร์แชร์ที่ไม่ผ่านเงื่อนไข โค้ดรองรับโฟลเดอร์สำรอง `DormManagement Private Slips` ผ่าน `PRIVATE_SLIP_FOLDER_ID` ข้อผิดพลาดในการเข้าถึงโฟลเดอร์ไม่ได้ทำให้สลับที่เก็บเสมอไป

หน้าเว็บอ่านสลิปผ่าน `getBillSlip` โดยส่ง token และ `billId` Backend ตรวจบัญชีที่ยังเปิดใช้งานและสิทธิ์ก่อนคืนรูป สลิปจำกัดขนาด 10 MB; `PaymentSlips` เก็บรายการล่าสุด และ `SlipReviews` เก็บประวัติการรับ/ตรวจ

**รูปโปรไฟล์:** เก็บใน `DormManagement Avatars` หน้าเว็บรับ JPG/PNG/WebP ไม่เกิน 2 MB และให้ครอปก่อนส่ง รูปโหลดผ่าน `getOwnAvatar` ของผู้ล็อกอิน พร้อมภาพสำรองเมื่อโหลดไม่สำเร็จ ขั้นตอนอัปโหลดปัจจุบันยังตั้งไฟล์เป็น `ANYONE_WITH_LINK` จึงไม่ควรถือว่ารูปโปรไฟล์เป็นไฟล์ส่วนตัวเพียงเพราะโหลดผ่าน API

ระบบพยายามรักษาไฟล์รูปเดิมไว้หากการบันทึกรูปใหม่ล้มเหลว แต่การเขียนหลายชีต/Drive ไม่ใช่ธุรกรรมฐานข้อมูลแบบ atomic ควรตรวจข้อมูลและไฟล์หากเกิดข้อผิดพลาดระหว่างบันทึก

ดูรายละเอียดการตรวจและย้ายสิทธิ์สลิปใน [backend/SLIP_PRIVACY.md](backend/SLIP_PRIVACY.md) เอกสารเดิมอาจเรียกบทบาทผู้ดูแลว่า `SUPER_ADMIN` ซึ่งโค้ดปัจจุบันรองรับเป็นชื่อเดิมของ `ADMIN`

## เผยแพร่ Frontend

สำหรับโฮสต์ที่รองรับ Vite เช่น Vercel ให้ตั้งค่าของโปรเจ็กต์ดังนี้:

| รายการ | ค่า |
|---|---|
| Root Directory | `frontend` |
| Build Command | `npm run build` |
| Output Directory | `dist` |

ตรวจ `API_URL` ก่อน build และตั้ง `FRONTEND_URL` เป็นโดเมนที่ใช้งานจริง ลิงก์ `localhost` ไม่เหมาะสำหรับส่งให้พนักงานคนอื่น ทุกครั้งที่เปลี่ยนสัญญา API เช่น รูปโปรไฟล์หรือการตรวจสลิป ควรเผยแพร่ Frontend และ Backend เวอร์ชันที่ทำงานร่วมกัน

## การทดสอบ

หลังติดตั้ง dependencies ใน `frontend` แล้ว รันจาก root ของโปรเจ็กต์:

```bash
node --test tests/*.test.cjs
npm --prefix frontend run build
git diff --check
```

ชุดทดสอบครอบคลุมการตอบกลับ API, ลิงก์เชิญ, บทบาท, รูปโปรไฟล์, สิทธิ์สลิป, หน้าต่างตรวจสลิป และกระบวนการยืนยัน/ปฏิเสธ โดยจำลองบริการ Apps Script และ LINE ไม่ใช่การทดสอบเชื่อมต่อบัญชี Google หรือ LINE จริง บางชุดอ่านฟังก์ชันจาก `backend/Line.js` จึงต้องมีไฟล์ local นี้ก่อนทดสอบ

หลัง deploy ควรทดสอบบัญชีแต่ละบทบาท การรับข้อความ LINE การผูกห้อง การรับสลิป การแสดงรูป และการแจ้งผลตรวจด้วยข้อมูลทดสอบก่อนใช้งานจริง

## การแก้ปัญหาเบื้องต้น

| อาการ | จุดที่ควรตรวจ |
|---|---|
| HTTP 404 หรือไม่พบ action | `API_URL`, deployment และเวอร์ชัน Backend ให้ตรงกับ Frontend |
| `SLIP_FOLDER` | ID โฟลเดอร์ สิทธิ์ของบัญชีผู้เผยแพร่ การอนุญาต Drive และผลจาก `checkSlipFolder()` |
| `SLIP_RECORD` | การเขียนชีตและการเปลี่ยนข้อมูลบิล/การผูก LINE ระหว่างรับสลิป รูปอาจเก็บใน Drive แล้วแต่บิลยังไม่สำเร็จ |
| พบบิลซ้ำหรือรหัสบิลไม่ถูกต้อง | `billId`, `billNo` และข้อมูลผู้เช่าใน Bills ตรวจหลักฐานก่อนแก้หรือลบรายการ |
| สลิปเข้าผิดห้อง | ตรวจ LineLinks → Tenants → Rooms → Bills และเวอร์ชันที่ deploy ไม่ย้ายสลิปโดยเดาจากรูปเพียงอย่างเดียว |
| รูปโปรไฟล์ไม่แสดง | action `getOwnAvatar`, `avatarFileId`, ไฟล์ใน Drive และบัญชีที่รัน Backend |
| ลิงก์เชิญไม่พร้อม | `STAFF_SIGNUP_CODE`, `FRONTEND_URL` และบัญชี OWNER/ADMIN ที่ยังเปิดใช้งาน |
| Commit ไม่ได้เพราะ unmerged files | แก้ merge conflict, ทดสอบ, stage ไฟล์ที่แก้ และทำ merge commit ก่อน push |

ตรวจรายละเอียดข้อผิดพลาดจาก Apps Script Executions โดยไม่เผยแพร่ token รหัสผ่าน หรือข้อมูลส่วนบุคคลใน log สาธารณะ

## ข้อจำกัดและเอกสารประกอบ

- ระบบรองรับหอพักเดียว ไม่ใช่ระบบแยกข้อมูลหลายหอ
- การลงทะเบียน LINE ด้วยเลขห้องยังไม่ใช่การพิสูจน์ตัวตนกับผู้เช่าอย่างเข้มงวด แม้มีการป้องกันข้อมูลซ้ำและเปลี่ยนการผูกแล้ว
- ประสิทธิภาพและความพร้อมใช้งานขึ้นอยู่กับบริการ Google, LINE และโฮสต์ Frontend รวมถึงโควตาและการตั้งค่าบัญชี จึงไม่รับประกันว่าไม่มีค่าใช้จ่ายทุกกรณี
- ควรสำรอง Spreadsheet และไฟล์หลักฐานก่อนย้ายข้อมูลหรือปรับสิทธิ์

- [การจัดเก็บและสิทธิ์สลิป](backend/SLIP_PRIVACY.md)
